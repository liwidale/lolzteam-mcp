AI-ассистент не может сам читать LOLZTEAM и LZT Market: контент закрыт API с авторизацией, собственными параметрами, пагинацией и лимитами запросов. LOLZTEAM MCP оборачивает официальные Forum API и Market API в 24 инструмента только для чтения, которые может вызывать любой клиент с поддержкой Model Context Protocol. Ассистент ищет темы и сообщения, читает обсуждение страница за страницей, находит пользователей, ищет объявления маркета с фильтрами категорий, открывает объявление и проверяет продавца. Результаты приходят в компактном JSON со ссылками на исходные страницы. Каталог эндпоинтов генерируется из официальных документов OpenAPI, поэтому новые методы и параметры API становятся доступны без нового кода.

## Установка

Установка занимает три шага: установить Node.js, получить токен API и выполнить одну команду настройки. Команда проверяет токен и добавляет сервер в ваши AI-клиенты.

### 1. Установите Node.js

LOLZTEAM MCP работает на Node.js 22.18 или новее. Проверьте установленную версию:

```bash
node --version
```

Если команда не найдена или показывает версию ниже `v22.18.0`:

- **Windows и macOS.** Скачайте установщик LTS с [nodejs.org](https://nodejs.org/) и запустите его.
- **Linux.** Установите Node.js 22 или 24 из пакетов вашего дистрибутива или через менеджер версий, например [nvm](https://github.com/nvm-sh/nvm).

После установки откройте новое окно терминала, чтобы команды `node` и `npx` стали доступны.

### 2. Получите токен API

1. Войдите в LOLZTEAM и создайте API-клиент на странице [lolz.live/account/api/client-add](https://lolz.live/account/api/client-add).
2. Получите токен доступа на странице [lolz.live/account/api/get-token](https://lolz.live/account/api/get-token) и выберите области доступа:

| Область  | Нужна для                                                                                                                               |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `read`   | Всех инструментов чтения форума.                                                                                                        |
| `basic`  | `forum_get_user`.                                                                                                                       |
| `post`   | `forum_search`. Официальная документация требует эту область для эндпоинтов поиска. Сервер использует её только для поисковых запросов. |
| `market` | Всех инструментов `market_*`.                                                                                                           |

Для доступа к Market API также нужно 200 симпатий на форуме или платная подписка на Market API. Без неё инструменты маркета возвращают ошибку `forbidden`, а инструменты форума продолжают работать.

Не передавайте токен другим людям. Любой, у кого он есть, может пользоваться API от имени вашего аккаунта.

### 3. Запустите настройку

```bash
npx -y lolzteam-mcp setup
```

Команда скачивает последнюю версию, а затем:

1. Запрашивает токен. Ввод скрыт.
2. Проверяет токен в обоих API и показывает, какому аккаунту он принадлежит. Если токен отклонён, настройка останавливается и ничего не меняет.
3. Находит установленные MCP-клиенты: Claude Desktop, Cursor и Windsurf.
4. Спрашивает, какие из них настроить. `Enter` настраивает все.
5. Добавляет сервер `lolzteam` в файл конфигурации каждого клиента. Другие серверы и настройки остаются как есть, а прежний файл сохраняется рядом с расширением `.bak`.
6. Выводит команду для Claude Code.

Обычно это выглядит так:

```text
Настройка LOLZTEAM MCP 1.0.0
Создайте API-клиент на https://lolz.live/account/api/client-add, затем получите токен на https://lolz.live/account/api/get-token с областями read, basic, post и market.
Токен API (ввод скрыт):
Проверяю токен...
Forum API: вход выполнен как your_name.
Market API: доступен.
Найдены MCP-клиенты:
  1. Claude Desktop (C:\Users\you\AppData\Roaming\Claude\claude_desktop_config.json)
  2. Cursor (C:\Users\you\.cursor\mcp.json)
Какие клиенты настроить, номера через запятую. Enter, чтобы настроить все:
Claude Desktop: сервер lolzteam добавлен в C:\Users\you\AppData\Roaming\Claude\claude_desktop_config.json
Cursor: сервер lolzteam добавлен в C:\Users\you\.cursor\mcp.json

Claude Code: выполните эту команду, подставив свой токен вместо <token>:
  claude mcp add --transport stdio --scope user --env LOLZTEAM_TOKEN=<token> lolzteam -- cmd /c npx -y lolzteam-mcp@latest

Перезапустите настроенные клиенты. Сервер lolzteam и его инструменты появятся после перезапуска.
```

Перезапустите настроенные клиенты. 24 инструмента появятся у сервера `lolzteam`.

Настройка говорит на языке вашей системы. Чтобы выбрать язык, запустите её с `LOLZTEAM_LOCALE=ru` или `LOLZTEAM_LOCALE=en`. Выбранный язык сохраняется и для сервера.

#### Параметры настройки

| Параметр         | Что делает                                                                                                                                                                       |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--yes`          | Настраивает все найденные клиенты без вопросов.                                                                                                                                  |
| `--client <id>`  | Настраивает только этот клиент: `claude-desktop`, `cursor` или `windsurf`. Повторите для нескольких клиентов. Нужен, если клиент ещё ни разу не запускался и его папки пока нет. |
| `LOLZTEAM_TOKEN` | Переменная окружения с токеном. Настройка берёт токен из неё и не спрашивает, поэтому её можно запускать из скриптов.                                                            |

Например, настроить только Cursor без вопросов в macOS или Linux:

```bash
LOLZTEAM_TOKEN=your-token npx -y lolzteam-mcp setup --yes --client cursor
```

### Claude Code

Claude Code хранит свой список серверов. Добавьте сервер одной командой, подставив свой токен вместо `your-token`.

macOS и Linux:

```bash
claude mcp add --transport stdio --scope user --env LOLZTEAM_TOKEN=your-token lolzteam -- npx -y lolzteam-mcp@latest
```

Windows:

```bash
claude mcp add --transport stdio --scope user --env LOLZTEAM_TOKEN=your-token lolzteam -- cmd /c npx -y lolzteam-mcp@latest
```

Проверьте подключение командой `claude mcp list`: в списке должен быть `lolzteam`.

### Обновление

Конфигурация запускает `npx -y lolzteam-mcp@latest`, поэтому npm скачивает свежую опубликованную версию, когда клиент запускает сервер. Чтобы получить новый выпуск, перезапустите клиент. Повторно запускать настройку нужно, только чтобы сменить токен или добавить ещё один клиент.

### Установка из исходников

Подходит, чтобы запустить свои изменения или ещё не опубликованную версию. Кроме Node.js нужен Git.

```bash
git clone https://github.com/liwidale/lolzteam-mcp.git
cd lolzteam-mcp
npm ci
npm run build
node dist/index.js setup
```

Если настройка запущена из клонированной папки, она записывает в конфигурацию клиента полный путь к `node` и к `dist/index.js` вместо `npx`. Для обновления подтяните новые коммиты и выполните `npm ci` и `npm run build`.

### Удаление

1. Удалите запись `lolzteam` из файла конфигурации каждого клиента или восстановите файл `.bak`, который сохранила настройка. Для Claude Code выполните `claude mcp remove lolzteam --scope user`.
2. Перезапустите клиенты.
3. Отзовите токен на [lolz.live/account/api](https://lolz.live/account/api), если он больше не нужен.

## Что вы получаете

- **Поиск и чтение форума.** Полнотекстовый поиск по темам, сообщениям и записям в профилях, списки тем с фильтрами и сортировкой, полный текст тем и сообщений, комментарии, опросы и теги.
- **Поиск людей.** Поиск пользователей по началу имени, публичные профили и список того, что пользователь написал.
- **Поиск по маркету с настоящими фильтрами.** Поиск в любой из 23 категорий маркета или во всех сразу по цене, валюте, происхождению аккаунта, продавцу и фильтрам категорий из официальной документации, например играм Steam или Telegram Premium.
- **Проверка объявлений и продавцов.** Одно объявление с атрибутами, гарантией и статистикой продавца, отзывы о продавце и оценка инвентаря Steam.
- **Вывод, который бережёт контекст.** Каждый инструмент возвращает компактный JSON без флагов прав и HTML-дубликатов. Длинные тексты обрезаются по лимиту, который задаёте вы, и помечаются как обрезанные.
- **Ссылки на источник.** Темы, сообщения, пользователи и объявления содержат ссылку на сайт, если API её отдаёт.
- **Все эндпоинты чтения, всегда актуальные.** Три универсальных инструмента дают доступ ко всем 113 эндпоинтам чтения обоих API, включая те, для которых нет отдельного инструмента. Ежедневный workflow скачивает официальные документы OpenAPI и открывает pull request, когда API меняется.
- **Только чтение.** Сервер никогда не публикует, не редактирует, не покупает, не продаёт и не меняет настройки. Ни один инструмент этого не умеет, поэтому вы не нарушаете правило форума о сообщениях, написанных LLM.
- **Предсказуемые ошибки.** Сбой возвращается как структурированная ошибка с кодом, сообщением API, подсказкой и, для лимитов, временем ожидания.

## Начало работы

После настройки и перезапуска клиента спросите ассистента о чём-нибудь, для чего нужен форум или маркет:

- «Что пишут на форуме LOLZTEAM о восстановлении Steam Guard? Перескажи три самые обсуждаемые темы.»
- «Найди самые дешёвые аккаунты Steam с CS2 Prime и без VAC-бана дешевле 500 рублей. Проверь отзывы о продавцах.»
- «Кто такой пользователь `example` и что он писал в последнее время?»

Ассистент сам выбирает инструменты. Большинство клиентов показывают каждый вызов инструмента и в первый раз спрашивают разрешение, так что видно, какие запросы уходят в API.

## Использование

Все инструменты работают только на чтение и помечены MCP-аннотацией `readOnlyHint`. Необязательные параметры можно не передавать.

### Инструменты форума

| Инструмент                  | Что делает                                                                | Основные параметры                                                                                              |
| --------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `forum_search`              | Полнотекстовый поиск по темам, сообщениям и записям в профилях.           | `query`, `type` (`all`, `threads`, `posts`, `profile_posts`), `tag`, `forum_id`, `user_id`, `page`, `limit`     |
| `forum_list_categories`     | Список категорий верхнего уровня.                                         | `parent_category_id`, `parent_forum_id`                                                                         |
| `forum_list_forums`         | Разделы форума с ID и числом тем. Описания, ссылки и префиксы по запросу. | `parent_category_id`, `parent_forum_id`, `detailed`, `include_prefixes`                                         |
| `forum_list_threads`        | Темы раздела с фильтрами и сортировкой.                                   | `forum_id`, `title`, `creator_user_id`, `prefix_ids`, `tag_id`, `period`, `order`, `direction`, `page`, `limit` |
| `forum_get_thread`          | Одна тема с полным первым сообщением и, по желанию, опросом.              | `thread_id`, `include_poll`                                                                                     |
| `forum_list_posts`          | Сообщения темы постранично.                                               | `thread_id`, `page_of_post_id`, `order`, `page`, `limit`                                                        |
| `forum_get_post`            | Одно сообщение с полным текстом.                                          | `post_id`                                                                                                       |
| `forum_list_post_comments`  | Комментарии к сообщению.                                                  | `post_id`, `before_comment_id`                                                                                  |
| `forum_get_user`            | Публичный профиль пользователя.                                           | `user_id` (число или `me`)                                                                                      |
| `forum_find_users`          | Пользователи, чьё имя начинается с заданного текста.                      | `username`                                                                                                      |
| `forum_list_user_content`   | Темы и сообщения пользователя.                                            | `user_id`, `page`, `limit`                                                                                      |
| `forum_find_tags`           | Теги по началу слова или популярные теги.                                 | `query`                                                                                                         |
| `forum_list_tagged_threads` | Темы с тегом.                                                             | `tag_id`, `page`, `limit`                                                                                       |

Инструменты, которые возвращают текст сообщений, принимают `text_length`, максимальное число символов на элемент. Текст сверх лимита заменяется пометкой `[truncated, N more characters]`, поэтому ассистент знает, что полный текст можно получить отдельно.

### Инструменты маркета

| Инструмент                         | Что делает                                                              | Основные параметры                                                                                                                                                           |
| ---------------------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `market_search`                    | Поиск объявлений в одной категории или во всех.                         | `category`, `title`, `min_price`, `max_price`, `currency`, `order_by`, `origin`, `exclude_origin`, `seller_id`, `not_sold_before`, `filters`, `include_attributes`, `cursor` |
| `market_get_item`                  | Полная информация об объявлении.                                        | `item_id`, `description_length`                                                                                                                                              |
| `market_get_category_filters`      | Фильтры категории с типами и допустимыми значениями. Работает без сети. | `category`                                                                                                                                                                   |
| `market_list_categories`           | Категории маркета по данным API.                                        | нет                                                                                                                                                                          |
| `market_list_category_games`       | Поиск игр категории и их ID для фильтров по играм.                      | `category`, `query`, `limit`                                                                                                                                                 |
| `market_get_seller_feedback`       | Отзывы покупателей о продавце с числом положительных и отрицательных.   | `seller_id`, `type`, `category_id`, `exclude_automatic`, `page`, `limit`                                                                                                     |
| `market_get_steam_inventory_value` | Оценка инвентаря Steam объявления для одной игры.                       | `item_id`, `app_id`, `currency`                                                                                                                                              |
| `market_list_currencies`           | Поддерживаемые валюты и курсы.                                          | нет                                                                                                                                                                          |

Фильтры конкретной категории передаются в объекте `filters` под их именами из API. Сначала вызовите `market_get_category_filters`, чтобы увидеть их. Например, поиск аккаунтов Steam с CS2 без VAC-бана и с файлом Steam Guard:

```json
{
  "category": "steam",
  "max_price": 500,
  "order_by": "price_to_up",
  "filters": { "game[]": [730], "no_vac": true, "mafile": "yes" }
}
```

Фильтры-массивы принимают список. Фильтры вроде `hours_played` принимают объект вида `{"730": 100}`. Фильтры «да или нет» принимают `yes`, `no` или `nomatter`. Неизвестные фильтры и значения вне документированного списка отклоняются до отправки запроса.

Результаты поиска содержат основные поля объявления: цену, происхождение, гарантию, статистику продавца с суммой отзывов, ссылку и короткое описание. Включите `include_attributes`, чтобы получить и атрибуты категории, например уровень Steam, игры, баны и стоимость инвентаря. `market_get_item` всегда возвращает их все, а даты переводит в ISO 8601.

### Универсальные инструменты

Эти инструменты покрывают все эндпоинты чтения из сгенерированного каталога, включая эндпоинты, которые появятся в API после выхода этой версии.

| Инструмент              | Что делает                                                                         | Основные параметры                            |
| ----------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------- |
| `api_list_endpoints`    | Список доступных эндпоинтов одного или обоих API, по желанию с фильтром по словам. | `service`, `query`                            |
| `api_describe_endpoint` | Параметры одного эндпоинта с типами, допустимыми значениями и описаниями.          | `service`, `operation`                        |
| `api_call_endpoint`     | Вызывает эндпоинт с проверенными параметрами и возвращает очищенный ответ.         | `service`, `operation`, `params`, `max_chars` |

Ассистент использует их, когда отдельного инструмента нет, например чтобы прочитать трофеи пользователя, комментарии к отзыву или свежие темы по всему форуму:

```json
{
  "service": "forum",
  "operation": "Users.Trophies",
  "params": { "user_id": 1 }
}
```

Параметры сверяются с официальной документацией до отправки запроса: неизвестные имена, неверные типы, значения вне документированного списка и пропущенные обязательные параметры отклоняются. Ответы проходят ту же очистку, что и у остальных инструментов: удаляются данные для входа, личные поля аккаунта, флаги прав и HTML-дубликаты. Ответ больше `max_chars` возвращается как фрагмент с подсказкой, как сузить запрос.

### Пагинация

- Списки форума возвращают `pagination` с полями `page`, `pages`, `total` и `next_page`. Передайте `next_page` в `page`, чтобы продолжить.
- Поиск по маркету возвращает `has_next_page` и `next_cursor`. Передайте `next_cursor` в `cursor`, чтобы продолжить.
- Комментарии к сообщению возвращают `oldest_comment_id`. Передайте его в `before_comment_id`, чтобы загрузить более старые.

### Ошибки

Неудачный вызов возвращает `isError: true` и JSON такого вида:

```json
{
  "error": {
    "code": "rate_limited",
    "message": "The Market API rate limit was reached. Try again later.",
    "status": 429,
    "endpoint": "GET /steam",
    "retry_after_seconds": 12,
    "hint": "Wait at least retry_after_seconds before calling this API again."
  }
}
```

| Код                    | Значение                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------- |
| `invalid_input`        | Аргумент отсутствует, вне диапазона или не является документированным фильтром.     |
| `not_configured`       | Для этого API не задан токен.                                                       |
| `bad_request`          | API отклонил параметры. Причина в `api_messages`.                                   |
| `unauthorized`         | Токен недействителен или истёк.                                                     |
| `forbidden`            | У токена нет нужной области или у аккаунта нет доступа к контенту или к Market API. |
| `not_found`            | Тема, сообщение, пользователь или объявление не существует или скрыто.              |
| `rate_limited`         | Достигнут лимит запросов. `retry_after_seconds` показывает, сколько ждать.          |
| `upstream_unavailable` | API вернул ошибку сервера после повторных попыток.                                  |
| `timeout`              | API не ответил за `LOLZTEAM_TIMEOUT_MS`.                                            |
| `network_error`        | Не удалось подключиться к API.                                                      |
| `invalid_response`     | API ответил не в JSON или ответ слишком большой.                                    |
| `cancelled`            | Клиент отменил вызов.                                                               |

## Настройка

Сервер читает переменные окружения, которые передаёт ему MCP-клиент.

| Переменная                        | По умолчанию             | Описание                                                                                                                                                                                                               |
| --------------------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `LOLZTEAM_TOKEN`                  | нет                      | Токен для обоих API.                                                                                                                                                                                                   |
| `LOLZTEAM_FORUM_TOKEN`            | `LOLZTEAM_TOKEN`         | Отдельный токен для Forum API.                                                                                                                                                                                         |
| `LOLZTEAM_MARKET_TOKEN`           | `LOLZTEAM_TOKEN`         | Отдельный токен для Market API.                                                                                                                                                                                        |
| `LOLZTEAM_FORUM_BASE_URL`         | `https://api.lolz.live`  | Адрес Forum API. Официальная документация также указывает `https://api.lolz.team` и `https://api.zelenka.guru`.                                                                                                        |
| `LOLZTEAM_MARKET_BASE_URL`        | `https://api.lzt.market` | Адрес Market API.                                                                                                                                                                                                      |
| `LOLZTEAM_LOCALE`                 | нет                      | Язык сервера и сообщений API, например `en` или `ru`. На нем выводятся описания инструментов, ошибки и подсказки, а API получает его в документированном параметре `locale`. Языки без перевода заменяются английским. |
| `LOLZTEAM_TIMEOUT_MS`             | `60000`                  | Тайм-аут одного HTTP-запроса, от 1000 до 600000.                                                                                                                                                                       |
| `LOLZTEAM_MAX_RETRIES`            | `2`                      | Повторы после 429, ответа 5xx или сетевой ошибки, от 0 до 5.                                                                                                                                                           |
| `LOLZTEAM_MAX_RATE_LIMIT_WAIT_MS` | `15000`                  | Самое долгое ожидание, на которое согласен сервер, прежде чем вернуть `rate_limited`, от 0 до 120000.                                                                                                                  |

Сервер запускается и без токена, чтобы клиент мог получить список инструментов. Вызовы API без токена возвращают `not_configured`.

### Лимиты запросов

Сервер ведёт собственный бюджет запросов для каждого API по лимитам из официальной документации и замедляется раньше, чем API начнёт отказывать:

| API    | Запросы                                | Лимит        |
| ------ | -------------------------------------- | ------------ |
| Forum  | Запросы `GET`                          | 300 в минуту |
| Forum  | Поиск, который использует `POST`       | 30 в минуту  |
| Market | Поиск по категориям и `GET /{item_id}` | 120 в минуту |
| Market | Остальные запросы `GET`                | 300 в минуту |

Сервер также учитывает заголовки `X-RateLimit-Remaining`, `X-RateLimit-Reset` и `Retry-After`. Если ждать нужно дольше `LOLZTEAM_MAX_RATE_LIMIT_WAIT_MS`, инструмент возвращает `rate_limited` с `retry_after_seconds` и не блокирует разговор.

В более старом разделе документации маркета упоминается более строгий лимит: 20 поисковых запросов по категориям в минуту. Если ваш аккаунт упрётся в него, сервер вернёт `rate_limited` со временем ожидания от API.

## Безопасность

- **Только чтение.** Сервер вызывает только документированные эндпоинты чтения, эндпоинты поиска форума и массовое получение объявлений, и все они проходят политику, описанную в разделе [Обновление вместе с API](#обновление-вместе-с-api). В нём нет кода, который публикует, редактирует, удаляет, покупает, продаёт, переводит деньги или меняет настройки.
- **Секреты не попадают в результаты.** Токен передаётся только в заголовке `Authorization` на настроенный адрес API. Он никогда не появляется в результатах инструментов и в логах, а сообщения API, в которых он встречается, маскируются.
- **Чувствительные данные объявлений удаляются.** Из результатов маркета удаляются поля с данными для входа, паролями, cookies, `.mafile`, кодами из почты, номерами телефонов, личными заметками и сведениями о покупателе, даже если аккаунт токена может их видеть.
- **Личные данные профиля не раскрываются.** Результаты по пользователям форума содержат только публичные поля профиля, без баланса, почты и секретного ответа, даже для `me`.
- **Внешний контент считается данными.** Тексты форума и маркета пишут другие люди. Сервер удаляет невидимые символы и символы управления направлением текста, никогда не интерпретирует текст и сообщает ассистенту в инструкциях и описаниях инструментов, что это только данные.
- **Строгая проверка входных данных.** Каждый аргумент проверяется по схеме с диапазонами и документированными значениями. Идентификаторы в пути должны быть положительными целыми числами или `me`, фильтры маркета должны существовать в официальной документации, а адреса API должны использовать HTTPS.
- **Никакого стороннего кода во время работы.** У пакета нет зависимостей, поэтому при установке добавляется только его собственный код. Протокол MCP, проверка аргументов и HTTP-клиент входят в проект и покрыты тестами, которые работают через официальный клиент MCP SDK.
- **Только локально.** Сервер работает через stdio и не открывает сетевой порт. Он ничего не отправляет никуда, кроме двух настроенных API. Телеметрии нет.

> [!WARNING]
> **Не позволяйте ассистенту писать на форуме.** Пункт 2.1 [правил LOLZTEAM](https://lolz.team/rules/) запрещает использовать любые LLM (GPT) для написания сообщений за вас на форуме в автоматическом или ручном режиме. Частичное использование для написания статей не запрещено. Поэтому сервер только читает. Доработка, которая публикует сообщения или использует параметры API для записи, например область `post` для чего-то кроме поиска, может привести к блокировке аккаунта.

Соблюдайте правила LOLZTEAM и условия API, когда используете данные, которые возвращает сервер.

## Решение проблем

**`npx` или `node` не найдены.** Node.js не установлен или терминал открыт до установки. Установите Node.js, как описано в разделе [Установка](#установка), и откройте новый терминал.

**Настройка не находит клиент.** Клиент создаёт папку конфигурации при первом запуске. Запустите клиент один раз и повторите настройку или укажите его через `--client`, например `--client cursor`.

**Настройка сообщает, что файл содержит некорректный JSON.** В файле конфигурации клиента синтаксическая ошибка, и настройка его не трогает. Исправьте файл или уберите его и запустите настройку снова.

**Инструменты не появляются в клиенте.** Полностью перезапустите клиент, включая значок в трее. Затем выполните в терминале `npx -y lolzteam-mcp@latest --version`: если Node.js и npm работают, команда выведет версию. При установке из исходников проверьте, что пути в конфигурации абсолютные и что `npm run build` завершился.

**Каждый вызов возвращает `not_configured`.** Клиент не передаёт `LOLZTEAM_TOKEN` серверу. Запустите настройку снова или укажите токен в блоке `env` конфигурации сервера, а не в профиле оболочки.

**`unauthorized`.** Токен недействителен или истёк. Создайте новый и запустите настройку снова.

**`forbidden` от `forum_search`.** У токена нет области `post`. Остальные инструменты форума работают без неё.

**`forbidden` от инструментов маркета.** У токена нет области `market` или аккаунт не соответствует условию доступа к Market API.

**`rate_limited`.** Подождите `retry_after_seconds`. Если это повторяется часто, просите меньше поисков подряд.

**Проверка токена из терминала.** При установке из исходников выполните:

```bash
LOLZTEAM_TOKEN=your-token npm run smoke
```

Команда вызывает несколько инструментов чтения через настоящие API и выводит `ok` или `FAIL` для каждого.

```bash
npm ci

npm run format:check

```

Тесты используют встроенный тестовый раннер Node.js и поддельный `fetch`, поэтому не обращаются к настоящим API и не требуют токена. Они покрывают настройку, HTTP-клиент с повторами, лимиты и разбор ошибок, генерацию каталога и политику только чтения, проверку параметров и каждый инструмент через настоящее MCP-подключение. Один из тестов падает, если сгенерированные каталоги не совпадают с документами OpenAPI в `openapi/`.

### Обновление вместе с API

Официальные документы OpenAPI лежат в `openapi/`. `npm run generate` превращает их в каталоги эндпоинтов `src/endpoints/forum.generated.ts` и `src/endpoints/market.generated.ts`. Универсальные инструменты и фильтры категорий маркета читают эти каталоги, поэтому новый эндпоинт, параметр или фильтр не требует кода. Отдельные инструменты сохраняют свои выбранные вручную параметры, а всё новое сразу доступно через универсальные инструменты.

Чтобы обновить вручную, скачайте свежие документы и пересоберите каталоги:

```bash
npm run sync
```

Команда выводит отчёт: добавленные, изменённые и удалённые эндпоинты, а также новые операции, которые исключила политика только чтения.

Workflow `Sync API` делает то же самое каждый день в 06:00 UTC. Если документы изменились, он запускает проверки и открывает или обновляет pull request `api-sync` с отчётом и результатом проверок. Просмотрите его и примите. Затем подтяните изменения и выполните `npm run build`.

Для работы workflow включите **Allow GitHub Actions to create and approve pull requests** в **Settings** > **Actions** > **General**.

Эндпоинт попадает в каталог, только если его пропускает `src/endpoints/policy.ts`:

- Только запросы `GET`, плюс документированные эндпоинты поиска и массовое получение объявлений. Остальные методы могут менять данные и исключаются.
- Никаких эндпоинтов, которым нужны личные области `conversate`, `payment` или `invoice`.
- Никаких эндпоинтов, путь которых ведёт к секретам: `.mafile`, коды из почты, письма, пароли, прокси.
- Никаких эндпоинтов, в документации которых есть предупреждение о побочных эффектах, например об отмене гарантии.
- Никаких эндпоинтов, которые возвращают личные данные владельца токена, например `/users/me` с балансом и почтой.

Новый эндпоинт, который не попал ни под одно правило, появится в pull request в разделе **Added endpoints**. Это момент, чтобы проверить, безопасно ли его открывать.

## Как это работает

1. MCP-клиент запускает сервер и получает список инструментов через stdio. Сервер сам реализует протокол MCP и не имеет зависимостей во время работы.
2. Когда ассистент вызывает инструмент, аргументы проверяются по схеме инструмента и сверяются с каталогом эндпоинтов, сгенерированным из официальных документов OpenAPI.
3. HTTP-клиент ждёт свободного места в локальном лимите, отправляет запрос с токеном и тайм-аутом и повторяет его при лимитах, ошибках сервера и сбоях сети с нарастающей задержкой.
4. Ответ сокращается до важных полей, тексты очищаются и обрезаются, а результат возвращается ассистенту в JSON.

Источником для каждого эндпоинта, параметра и поля ответа служили официальные документы OpenAPI, опубликованные вместе с документацией API.

## Участие в разработке

Issues и pull requests приветствуются. Изменения, которые позволяют серверу публиковать, редактировать или покупать, не принимаются, потому что правила форума запрещают сообщения, написанные LLM. Сервер должен оставаться только для чтения, каждый текст для пользователя должен лежать в `src/i18n/en.ts` и его переводах, каждый параметр должен опираться на официальную документацию API, новое поведение должно сопровождаться тестами, а перед pull request нужно запустить `npm test`, `npm run lint` и `npm run typecheck`.
